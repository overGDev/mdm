# Working in this repository

This project's documentation is managed with [mdm](https://github.com/overGDev/mdm), a CLI that turns a version-controlled set of Markdown sections into a single combined document. The structure is defined once in `mdm/schema.yaml`; everything else follows from it.

## Structure

- `mdm/schema.yaml` is the blueprint: it declares every section, its title, and its order. This is the file to edit when the document's structure changes.
- `mdm/paths.yaml` declares where `sections/`, `assets/`, and the combined output file live. Change these with `mdm paths set <key> <value>`, never by hand: the command also relocates the actual files and updates `.gitignore` and the CI workflow to match.
- `mdm/vars.yaml` holds key/value pairs referenced from section content as `{{var_name}}`, substituted when the document is built.
- `sections/` holds the actual Markdown content, one file or folder per schema entry. It's generated by `mdm sync` from the schema, not hand-built.
- The combined output file is generated by `mdm build` and committed by CI, not by hand. It's gitignored for that reason: don't add it back to version control.

## Making a change

- **Adding, renaming, or reordering a section**: edit `mdm/schema.yaml`, then run `mdm sync` to create or rename the corresponding file under `sections/`. Write the actual content there.
- **Changing a variable**: use `mdm var set <key> <value>` (or `get`/`unset`/`list`), never hand-edit `mdm/vars.yaml`.
- **Moving where sections, assets, or the output file live**: use `mdm paths set <sections|assets|output> <value>`. It moves the real files and keeps `.gitignore`/CI in sync; a manual `mv` will not.
- **Previewing the combined document**: run `mdm build` locally. This isn't required before pushing: the CI workflow rebuilds and commits the output on every branch push.

## Boundaries

- Don't hand-write files directly under `sections/` without a matching `mdm/schema.yaml` entry; `mdm sync` won't recognize them and `mdm build` will refuse to run until the schema and the folder agree.
- Don't edit the `*.assets` symlinks `mdm sync` creates inside `sections/`; they're regenerated on every sync run.
- Don't edit the combined output file directly. Changes made there are overwritten the next time CI (or a teammate) runs `mdm build`.

## Writing style

Section content is often drafted by Claude, but it still has to read as something a human wrote and can audit. Follow these rules when writing or editing a section:

- Separate paragraphs with a blank line between them, not a line break inside one:
```
Paragraph 1.

Paragraph 2.
```
- Use `-` as the bullet marker for lists.
- A bullet list that belongs to the paragraph right above it sticks directly under it, no blank line in between:
```
Paragraph 1 items:
- item 1
- item 2
```
- Don't use emojis.
- Don't use bold, italics, or other text styling unless the user asked for it or an existing pattern in the document already shows how it's applied.
- Don't add headers inside a section file. `mdm build` generates each section's header from `mdm/schema.yaml` when it merges the document; a header written inside the file breaks that structure.
